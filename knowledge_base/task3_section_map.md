# Task 3 (Post-Implementation Report) Section Map

**Task description:** A post-implementation report for the project proposed in Task 2. The report explains how the IT solution was implemented to resolve the identified problem, including methodology for project implementation. Tasks 1 and 2 must pass before Task 3 can be submitted.

**Tense:** Past tense — Task 3 describes a project that has been completed. All dates must be in the past.

**Critical guidance:**
- The rubric is mostly a checklist. Missing a single objective item can get the submission returned.
- Provide required content in a format easily identified and matched to the requirements.
- Use paragraphs with complete sentences for most sections.
- Do NOT write an outline.
- Do NOT leave sections blank — if nothing happened (e.g., no scope creep, no timeline variances), explain why.
- Most of Task 3 is updating Task 2 to past tense. Where Task 3 differs from Task 2, the differences are highlighted in this map's per-section notes.
- Tasks 2 and 3 dates do NOT need to match. Task 3 start dates can be adjusted so durations are maintained but end dates are in the past.

**Sections:**
- A — Summary
- B — Review of Other Work
  - B.1 Works Supporting Implementation
- C — Changes to Project Environment
- D — Methodology
- E — Project Goals and Objectives
- F — Project Timeline with Milestones
- G — Unanticipated Scope Creep
- H — Conclusion
  - H.1 Success of Project
- I — Appendices (3 artifacts)
- J — Sources (in-text citations and references)
- K — Professional Communication
- References

**Important: same letter, different meaning across tasks.** Several letters map to entirely different sections in Task 2 vs. Task 3 (e.g., Task 2 H = Outcome, Task 3 H = Conclusion). When students reference a section by letter, confirm which task they're discussing.
