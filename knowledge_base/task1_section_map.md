# Task 1 (Capstone Topic Approval) Section Map

**Task description:** A topic approval form that the student completes and submits directly to Assessments as Task 1. The assigned course instructor (or, in the future, an evaluator) either passes the submission or returns it with comments for revision. There is no email-to-instructor or signature step — Task 1 is submitted the same way as Tasks 2 and 3. The purpose is to ensure students start a project that can pass — not to lock in every detail of the eventual proposal.

**Tense:** Future tense — Task 1 describes a project to be done. Any date in the future is acceptable; dates do not need to align with Tasks 2 or 3.

**Critical guidance:**
- Task 1 is a **form**, not a paper. The form has four short sections the student fills in; the rubric (A-D) evaluates the resulting submission.
- The form is **submitted directly to Assessments** — there is no signature step and no emailing the form to an instructor. The course instructor passes the submission or returns it with comments.
- If you have questions about your topic *before* submitting, you can still email the assigned course instructor or the team inbox `ugcapstoneit@wgu.edu`. This is optional and is not part of submitting the form.
- **Changes from Task 1 to Task 2 are allowed and expected.** Evaluators do not compare Task 1 to Task 2 except for the approved topic. Task 1 only needs to show a project that *can* pass — it doesn't need to be the final form of the project.
- **It is acceptable to fabricate parts or all of the project.** If the project is being completed at work or at WGU, write Tasks 1 and 2 as if the project still needs to be done. Most students fabricate; that's expected.
- **REMOVE ALL TEXT IN RED** before submitting the form. The red text in the form is guidance for filling it out — it should not appear in the submitted version.
- The **human-subject research** certification question should almost always be answered **No.** It only applies if the student plans to collect data directly from human subjects. Most C769 projects do not.

**Structure of this map:**
1. **Topic Approval Form sections** — the substantive content the student provides
2. **Rubric items A-D** — the formal evaluation criteria applied to the submitted Task 1

These two tracks work together: the rubric is mostly satisfied by the form being correctly filled out and submitted.

**Form sections (in order):**
- The Client and the Problem
- The IT Solution
- Supporting Soft Deliverables (optional)
- Student Certification (three Yes/No questions)

**Rubric items (lettered A-D):**
- A — Topic Approval Form
- B — Restricted Information Authorization Form (if applicable)
- C — Sources (in-text citations and references)
- D — Professional Communication

**Same letter, different meaning across tasks.** Task 1's letters refer to top-level submission components, not paper sections. Task 1 A is "the form is complete"; Task 2 A is "Proposal Overview" (a paper section); Task 3 A is "Summary." When students reference a section by letter, confirm which task they're discussing.

# Topic Approval Form sections

## The Client and the Problem

**Form requirement:**
Name a specific client (real or fabricated) and describe their problem in 2-4 sentences. General descriptive or prescriptive projects are not allowed.

**What's required (your translation):**
- **Specific client.** Name a client (real or fabricated). "Company X" or "ABC Corp, a 40-person regional accounting firm" is fine. The client cannot be generic or unnamed ("a small business," "an organization").
- **Specific environment.** Describe the client's situation enough that the problem makes sense.
- **A problem solvable by technology.** The problem must be one that an IT deliverable can solve.
- **No purely descriptive or prescriptive projects.** A descriptive project analyzes a problem without solving it. A prescriptive project recommends action without implementing. Neither qualifies on its own.

## The IT Solution

**Form requirement:**
Identify the hardware or software to be installed, built, or upgraded as a permanent part of the client's environment, in 2-4 sentences. At least one hard IT deliverable must be present.

**What's required (your translation):**
- **At least one hard IT deliverable.** Hardware or software changes that become a permanent improvement to the client's environment. Examples: implementing a new firewall, deploying MFA, building a custom application, migrating to cloud infrastructure.
- **Permanent improvement.** The solution must be a lasting addition to the environment, not a one-time assessment or report.
- **Implementation, not investigation.** If the topic requires an initial assessment (as with many security projects), assume the evaluation has already concluded so the form can focus on implementing the solution.

## Student Certification

**Form requirement:**
Three Yes/No questions that must **all** be answered before submission:
1. Whether the student understands the project requirements (the project implements a hard IT deliverable for a specific client; real or fabricated is OK).
2. Whether the project involves human-subject research.
3. Whether the project uses restricted or proprietary information from an employer or third party.

**What's required (your translation):**
- **All three must be answered.** A blank certification question is the most avoidable return reason.
- **Question 1 (requirements understanding):** Answer **Yes** once the project meets the basic requirements — a hard IT deliverable for a specific (real or fabricated) client.
- **Question 2 (human-subject research):** Answer **No** unless the student plans to collect data directly from human participants (interviews, surveys, etc.), which is rarely needed for an IT capstone. Reading academic papers or citing studies is *not* human-subject research. If **Yes**, the student should contact the course instructor before submitting so IRB review can be coordinated.
- **Question 3 (restricted information):** Answer **No** if the project uses no restricted or proprietary information (the usual case when the project is fabricated or masked). If **Yes**, the student must also submit the Restricted Information Authorization Form (rubric item B).

## B — Restricted Information Authorization Form

**Rubric requirement (Competent):**
The "IT Capstone Project Restricted Information Authorization Form" is complete if restricted information is being used.

**What's required (your translation):**
- This form is required ONLY if the student answered **Yes** to Student Certification question 3 (the project uses proprietary or classified information from the student's employer or another third party).
- If the project does not use restricted information, the form is not needed and rubric item B passes automatically.
- Restricted information requires written authorization from the owner, submitted along with the form, before being included in the capstone.
- In most cases, the need for authorization can be avoided by fabricating or masking identifying information.

## C — Sources (in-text citations and references)

**Rubric requirement (Competent):**
The submission includes in-text citations for sources that are properly quoted, paraphrased, or summarized and a reference list that accurately identifies the author, date, title, and source location as available.

**What's required (your translation):**
Acknowledge sources with in-text citations and references for any content that is quoted, paraphrased, or summarized.

- Use a style-appropriate format (e.g., APA: (Author, Year)).
- Every in-text citation must have a matching reference; every reference must have at least one in-text citation.
- The reference list must include author, date, title, and source location (URL/journal/etc.) where available.
- Most Task 1 submissions will have few or no references because the form is largely the student's own project description. References apply primarily if the student cites prior work in The Client and the Problem or The IT Solution sections.
